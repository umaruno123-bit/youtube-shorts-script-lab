# 動画完成マニュアル(台本→テロップ→動画組み立て)

ShortsLabで台本を作った後、それを実際に「テロップ・画像入りの動画」まで
完成させる作業をClaude Codeにやらせるためのマニュアル。実際にやってみて
うまくいった方法・失敗した方法をすべて記録している。Claude Codeが使える
人であれば、このマニュアルを読ませるだけで同じ精度の作業を再現できるはず。

## 0. 全体の流れ

```
台本(ShortsLabのprepare/telop_manual.md) + VOICEVOX音声
        ↓
Premiere等で音声だけ並べた「空の動画」を作る(人間の作業)
        ↓
Claude Codeが音声を解析してタイミングを実測(★最重要)
        ↓
Claude Codeがテロップ+画像の静止画フレームを生成
        ↓
Claude Codeがffmpegで静止画→動画クリップ化→結合→元音声と合体
```

人間がやるのは「音声を並べる」「使いたい画像を用意する(ダウンロード
フォルダに入れておくなど)」「完成品を見て指示を出す」だけで、テロップの
配置・タイミング合わせ・動画の組み立ては全部Claude Codeに任せられる。

## 1. 必要な環境

| 用途 | ツール | インストール |
|---|---|---|
| 動画の読み書き・結合 | ffmpeg | `winget install ffmpeg` |
| 音声の実タイミング解析 | faster-whisper(Python) | `pip install faster-whisper` |
| テロップ画像の生成 | Pillow(Python) | `pip install Pillow` |
| 台本の文字起こし・ナレーション | VOICEVOX | 別途インストール、ローカルでHTTP APIとして動く |
| GitHub連携(任意) | GitHub CLI | `winget install GitHub.cli` |

**Windows特有の注意**: `winget install` した直後は、今開いているシェル
(Claude Codeが使っているBashセッションなど)のPATHにまだ反映されない。
新しいターミナルを開き直さない限り、コマンドが「見つかりません」になる。
対処法は2つ:

1. インストール先のフォルダを探して、そのセッション内だけ一時的にPATHへ
   追加する。例:
   ```bash
   export PATH="/c/Users/<user>/AppData/Local/Microsoft/WinGet/Packages/<パッケージフォルダ>/<バージョン>/bin:$PATH"
   ```
   (`find /c/Users/<user>/AppData/Local/Microsoft/WinGet/Packages -iname "ffmpeg.exe"` 等で
   実際のパスを探す)
2. 以降のffmpeg呼び出しは全部このexportを毎回のコマンドの先頭に付ける
   (Bashツールはコマンドごとにシェル状態がリセットされるため)。

## 2. 台本→テロップ分割→VOICEVOX投入

ここはShortsLabの `prepare` コマンドと `docs/telop_manual.md` で既にカバー
されている。要点だけ再掲:

- 台本は【フック】【本編】【締め・CTA】の構成で書く
- 尺は文字数÷実測の発話速度(このチャンネルなら7〜8文字/秒。動画の
  `duration_sec` とtranscriptの文字数から `shortslab.db` を見て逆算できる)
  で見積もる
- VOICEVOXに入れるテキストは「1行=1画面(1クリップ)」になるよう、
  `docs/telop_manual.md` の4法則で細かく分割してから渡す
- ナレーションを人間側でVOICEVOXから書き出し、Premiere等で音声トラックに
  並べた状態(映像はまだ空でよい)を「完成前の動画」としてClaude Codeに渡す

## 3. 音声とテロップのタイミングを合わせる(最重要の教訓)

### 3.1 やってはいけない方法

最初にやって失敗したのは、ffmpegの `silencedetect` フィルタで音声の
無音区間(息継ぎの間)を検出し、「検出された無音区間の順番」と「台本の
行の順番」を機械的に1対1で対応づける方法だった。

これは**一見もっともらしいが根本的に信頼できない**。理由:

- VOICEVOXの読み上げは意味の区切り以外の場所でも細かく間が空く
- 無音区間の「数」がたまたま台本の行数に近くても、対応関係が合っている
  保証はどこにもない
- 実際、この方法で作った動画は「テロップと喋っている内容が一致しない・
  支離滅裂」になった

**教訓: 音を実際に「聞いて」確認していないタイミング合わせは、当てずっぽう
と同じ。** 数が合っていそうに見えても信用しないこと。

### 3.2 正しい方法: Whisperで実際の発話を単語単位で文字起こしする

`faster-whisper` を `word_timestamps=True` で使うと、音声認識(AI)が実際に
「何が」「何秒何十分の一秒に」話されているかを単語単位で返してくれる。
これを台本作成時の想像ではなく**実測データ**として使う。

ShortsLabには専用コマンドを用意した:

```bash
shortslab timing "動画ファイル.mp4" --model medium --out timing_result.txt
```

出力例:

```
[  17.36 -   22.24] 誰もが壊れた残骸だと思ったが電池を入れ替えて電源を入れると
      17.36 -   17.62  誰
      17.62 -   17.82  も
      ...
```

`[開始 - 終了] 文全体` の行(セグメント)は、モデルが検出した自然な息継ぎ
の単位。その下のインデントされた行が、各文字/単語ごとの実測タイムスタンプ。

**使い方のコツ**:
- セグメントの区切りは「本当に間がある場所」の目安として信頼できる
  (無音検出と違い、実際の音響特徴とモデルの言語理解の両方から来ている)
- セグメントをまたいで文がつながっている(例: 前のシーンの台詞と次の
  シーンの台詞が実は1つの息継ぎでつながっている)ことも普通にあるので、
  「区切りたい場所」と「実際に区切れる場所」がズレていないか必ず確認する
- 台本のテキストと音声認識結果の文字は完全一致しないことがある
  (「湾岸戦争」→「ワンガン戦争」のような聞き取り誤りは普通に起きる)。
  **表示するテロップの文字は台本の正しい表記を使い、タイムスタンプだけ
  Whisperの結果から借りる**のが正しい使い方
- モデルサイズは `medium` を推奨(`small`より精度が上がる、`large`ほど
  遅くない)。60〜70秒の動画で数分程度で終わる

### 3.3 動画の一部だけ完成済みで「続き」を作る場合

既に一部だけテロップが入っている動画に続きを足す場合:

1. 動画を数秒おきにフレーム書き出しして(`ffmpeg -vf fps=1/10`)、
   どこまで内容が入っているか目視で確認する
2. 音量解析(`ffmpeg -af volumedetect`)で、見た目が空白になった後も
   ナレーション音声自体は続いているかを確認する(続いていることが多い =
   台本の後半部分の音声はもう録音済みで、テロップだけが追いついていない
   状態)
3. Whisperで全体を解析し、「既存のテロップが表示され終わる時刻」に一番
   近いセグメント区切りを継ぎ目にする
4. 継ぎ目より前の映像はそのままの動画から切り出し(`ffmpeg -t <秒> -an`
   で映像だけ)、継ぎ目より後を新規作成したテロップ動画に差し替えて結合、
   最後に元の音声(全体)を通しでミックスする

## 4. 既存デザインを踏襲する場合は「実測」する

前提の動画(第1弾)がある場合、その配色・フォントサイズ・余白を目分量で
真似ようとすると必ずズレる。Pillow/numpyでピクセルを直接調べて数値化する。

```python
from PIL import Image
import numpy as np

img = Image.open("既存フレーム.png").convert("RGB")
arr = np.array(img).astype(int)

# 背景色を隅のピクセルから取得
bg = tuple(arr[20, 20])

# テキスト行の上下端を検出(背景色でも白でもない行を「文字あり」とみなす)
is_dark = arr.sum(axis=2) < 250
for y in range(len(arr)):
    if is_dark[y].any():
        print(y, "この行に文字がある")
```

これで「フォントサイズは何ptに相当するか」「画像とテキストの間は何px
空いているか」を実測できる。実測した px 数を「〇mm」と言われた場合の
換算基準にすると精度が上がる(例: 実測した間隔が既存の指示"3mm"と
近い値になっていれば、そのdpi換算が正しいと確認できる)。

**単位の指定(mm)を受けたときの注意**: 動画のピクセル寸法とmmの対応は
プロジェクトのDPI設定に依存し、Claude側からは分からない。可能な限り
「既存フレームの実測値」から逆算する。新規に「〇mm」という指示だけが
来て実測できる手がかりが無い場合は、96dpi換算(1mm ≈ 3.78px)を仮定
しつつ、その仮定をユーザーに明示して後から修正できるようにしておく。

## 5. テロップ画面のレンダリング(Pillow)

### 5.1 画像の当てはめ方: 「収める」ではなく「覆う」

`ImageOps.contain`(画像全体を枠内に収める、余白ができる)ではなく、
**アスペクト比を保ったまま枠を隙間なく埋め、はみ出す部分をトリミングする**
方式(CSSでいう `object-fit: cover`)を使う。「画像をつぶすのはダメ、
はみ出すのはOK」という指示は、このcover方式を指している。contain方式で
実装すると指示と逆の見た目になるので注意。

```python
def place_image_cover(canvas, photo_path, x, y, band_w, band_h):
    photo = Image.open(photo_path).convert("RGB")
    src_w, src_h = photo.size
    scale = max(band_w / src_w, band_h / src_h)  # containならmin、coverはmax
    new_w, new_h = round(src_w * scale), round(src_h * scale)
    resized = photo.resize((new_w, new_h), Image.LANCZOS)
    left = (new_w - band_w) // 2
    top = (new_h - band_h) // 2
    cropped = resized.crop((left, top, left + band_w, top + band_h))
    canvas.paste(cropped, (x, y))
```

### 5.2 文字サイズは「基本サイズを維持、必要な時だけ縮小」

最初、長い行に合わせて自動縮小するロジックを作ったところ、短い行まで
不必要に縮小されて「全体的に文字が小さくなった」と指摘された。正しい
実装は「基準サイズでまず試し、余白の最低ラインを超える場合だけ縮小する」。

```python
def fit_font(draw, lines, max_width, target_size, min_size, font_path):
    size = target_size
    while size > min_size:
        font = ImageFont.truetype(font_path, size)
        widths = [draw.textbbox((0, 0), l, font=font)[2] for l in lines]
        if all(w <= max_width for w in widths):
            return font
        size -= 2
    return ImageFont.truetype(font_path, min_size)
```

`max_width` には「キャンバス幅 − 余白×2」を渡す。余白は最低ラインとして
守るべき値(例: 5mm/7mmなど、3節の実測 or 換算値)を使う。

### 5.3 「動き」を出す: 2段階表示

テロップを画像1枚に対して一括で全部表示すると、静止画が長時間続いて
「動きがない」と感じられる。実際の発話に合わせて**上段→少し遅れて下段**
の順で表示させると、音声とテロップが連動して見える。

やり方: 1つの「シーン(画像1枚)」につき、上段テキストだけの静止画と、
上段+下段テキストの静止画の**2枚**を作り、それぞれを対応する時間だけ
動画クリップ化して連結する。上段の表示開始時刻・下段の表示開始時刻は、
どちらも3節のWhisper実測タイムスタンプから取る(それぞれの文の実際の
発話開始時刻)。

## 6. 動画の組み立て(ffmpeg)

```bash
# 1. 各静止画フレームを、対応する秒数だけの動画クリップにする
ffmpeg -y -loop 1 -i frame.png -t <秒数> -r 30 -pix_fmt yuv420p -vf "scale=1080:1920" clip.mp4

# 2. 全クリップを結合(concat用のリストファイルを用意して)
#    file 'clip001.mp4'
#    file 'clip002.mp4'
#    ...
ffmpeg -y -f concat -safe 0 -i list.txt -an -c:v libx264 -preset fast -crf 18 -r 60 -vf fps=60 video_only.mp4

# 3. 元動画の音声を抽出(変更しない場合)
ffmpeg -y -i 元動画.mp4 -vn -c:a aac -b:a 192k audio.m4a

# 4. 映像と音声を合体、新しいファイル名で保存(元ファイルは絶対に上書きしない)
ffmpeg -y -i video_only.mp4 -i audio.m4a -c:v copy -c:a aac -b:a 192k -shortest 完成品.mp4
```

**大原則: 元のファイルは上書きしない。** `シーケンス01.mp4` を編集したら
`シーケンス01_2.mp4` のように必ず新しい連番で保存する。人間側が
Premiereで作業中のファイルを壊さないため。

## 7. 画像素材について

- 人間がダウンロードフォルダに用意した画像がある場合は、まずそれを内容
  確認してから使う(用途に合っているか、笑顔か、年代が合っているか等)
- 足りない場合はWeb検索で調達する。**CC0/パブリックドメインの素材を
  優先**し、そうでない場合は出典を明記する(表示するかどうかは指示に従う)
- **同じ画像を長時間・複数シーンで使い回さない**。話の展開(場面転換)ごと
  に別の画像に切り替える。手元の画像点数が足りない場合は追加で探す
- 実在の事件・災害など機微な内容を扱う画像は、人物の遺体や強い苦痛が
  写ったものは避け、資料写真的・引きの構図のものを選ぶ
- ダウンロードした画像は必ず一度目視で内容を確認してから使う(ファイル名
  だけで判断しない。AVIF等Pillowで直接読めない形式は変換してから確認する)

## 8. 事実確認を徹底する

- 台本に入れる「実話エピソード」は、それらしく聞こえても鵜呑みにせず
  Web検索で裏取りする
- 検索して出典が見つからない場合は、動画を完成させる前に必ずユーザーに
  「この部分は未確認です」と伝える。特に実在の人物・実在の災害など、
  誤情報が実害につながりうる題材は慎重に
- 検索で分かった事実(数値・日付・固有名詞)は、想像で書いていた部分より
  優先して差し替える

## 9. よくある詰まりポイント

| 症状 | 原因 | 対処 |
|---|---|---|
| コンソール出力が文字化けする | Windowsのコンソールが既定でUTF-8でない | `sys.stdout.reconfigure(encoding="utf-8")` をCLIの最初で呼ぶ、またはPython呼び出し時に `PYTHONIOENCODING=utf-8` を付ける |
| yt-dlp/ffmpegが `HTTP Error 429` で失敗する | 短時間に大量にリクエストしすぎ | リクエスト間に1〜2秒のsleepを挟む、429検知時は指数バックオフで再試行する |
| `winget install` 直後にコマンドが見つからない | PATHが現在のシェルに未反映 | 1節参照。インストール先を`find`で探してセッション内で`export PATH`する |
| ffmpegで`-t`に指定した秒数と実際の長さがズレる | フレーム境界に丸められる | 数十ミリ秒のズレは無視して良いことが多いが、気になる場合は前後の断片の合計が全体尺と一致するかを`ffprobe`で必ず確認する |
| 生成した動画が意図と違う | 確認せずに送ってしまった | 送る前に必ず`ffmpeg -ss <時刻> -frames:v 1`で要所のフレームを書き出し、目視確認してから渡す |

## 10. 作業の心構え

- 「たぶん合っている」ではなく実測・実際の音声認識で検証してから完成
  とする
- 人間の指示は数値も含めて正確に反映する。あいまいな単位(mm等)は実測
  できるなら実測、できないなら仮定を明示する
- 個人情報(実名・メールアドレス・住所など)は動画にもマニュアルにも
  含めない
- 元ファイルを壊さない(上書きしない、常に新しい連番で保存する)
